## Delivered behavior

- Install, activate, run, observe, reconcile, and rollback are independent revision-fenced
  transitions. Each external effect journals PREPARED and STARTED before invocation.
- A lost reply, timeout, target-side failure after STARTED, or absent required observation records
  UNKNOWN, retains the target lock, and permits reconciliation rather than blind retry.
- Reconciliation accepts only a proven exact applied state or exact safe pre-effect state.
  Contradictions and unexplained artifact/configuration revisions remain UNKNOWN.
- Missing, corrupt, or unhealthy candidates invoke the separately recorded rollback transition.
  Rollback completes only after exact prior artifact and configuration identities are observed;
  unexplained changes are preserved.
- The append journal now has a fsynced transition record and revision/data-digest/dead-owner
  recovery checks for crashes immediately before or after event persistence.
- Installed configuration discovery uses the conventional `~/.config/dev-fleet` authority;
  source checkouts retain repository-local discovery, with an explicit absolute
  `DEV_FLEET_CONFIG_ROOT` override.
- A deterministic, non-executing rollout plan freezes install-only, canary, soak, bounded batches,
  and fleet observation. Fixture plan SHA-256:

  It yields install-only on all four fixture hosts; canary/soak on `normandy`; batches
