## Delivered behavior

- `fault_campaign.py` freezes one causal identity containing the fixed seed, campaign, workflow,
  run, attempt, live T3 thread, Huyang workspace, deployment, plan, and target IDs. Its event stream
  is revision-fenced and SHA-256 chained; restart recovery replays only that durable stream.
- Custody is complete and disjoint. t3-steward owns schedule/workflow/lease; T3 owns
  thread/attempt/settlement; Huyang owns workspace/source revision/source transaction; UpKeeper
  owns deployment journal/lock/rollback and target application; Git owns repository/worktree/
  commit/durable-ref state; the target owns observed runtime state only.
- Each authorized effect has a deterministic ID derived from frozen campaign and attempt identity,
  sole owner, action, and input revision. PREPARED and STARTED are recorded before a modeled
  execution. A persisted STARTED or UNKNOWN effect cannot be replayed; exact reconciliation must
  first prove applied or not applied. Exact duplicate confirmations are idempotent, while
  contradictory receipts, foreign causal IDs, stale revisions, and authority mismatches fail
  closed.
- Observation envelopes carry producer, subject owner/revision, sequence, evidence digest, and
  campaign ID. Exact duplicates are inert, stale observations are retained but cannot advance
  state, current delayed observations can converge, and missing/future/conflicting observations
  report `RECOVERY_REQUIRED`.
- Cleanup is allowed only after convergence and only for routine owner-scoped residue. Dirty or
  foreign residue is preserved. A successful detached attempt cannot be cleaned until every
  produced commit is explicitly reachable from a durable successor-addressable Git ref.
- The code is a deterministic source model only. It performs no deployment, activation, restart,
  secret mutation, public exposure, push, pull request, or other live effect. homelab-infra Git
  plus Ansible remain deployment authority.
