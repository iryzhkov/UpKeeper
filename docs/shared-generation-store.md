# Candidate shared-generation store

Frozen Go API: `Open(root string) (*Store, error)`, `(*Store).Stage(repository, commit string) (Inspection, error)`, `Inspect() (Inspection, error)`, `SelectPrior(id string) (Inspection, error)`, and `Recover() (Inspection, error)`. Open initializes only an explicitly supplied absolute physical empty 0700 directory owned by the caller, or reopens a complete validated store. Store retains root/lock inode identities; every operation reacquires the same persistent flock and revalidates. Stage owns PrepareShared and its lifetime. No caller preparation or authority flag is accepted.

Receipt schema 1 has state candidate-inert, owner upkeeper, source_repository github.com/iryzhkov/UpKeeper, exact source_commit, owner_descriptor_sha256, source_sha256 (including owner.json), and sorted files with path, sha256, numeric mode 420, kind, logical_destination. Canonical bytes use canonjson.MarshalFile. Their SHA256 names generations/<id>; no ID is embedded in those bytes. Inspection reports the external ID, receipt and trusted-generated-source label. Empty selection has no ID. Store identity is a separate canonical schema_version/state/owner object, not an authority document.

Only candidate-current inside this scratch store is selected. Instructions and canonical skills are regular 0644 payloads; receipt.json and store.json are 0600; all store directories are 0700. Selection and rollback never write imports, installed namespaces, grants or old writers. Existing production callers do not import this package.

Linux acquisition checks physical ancestors, uses O_PATH before data opening, validates procfs, binds held descriptors to final paths and checks ownership, link counts, size, mode, hash and closure. Metadata is limited to 256 KiB, depth 12 and arrays/objects 1024; relative paths to 512 bytes and segments 255; each payload to 16 MiB and aggregate payload to 64 MiB. Non-Linux calls explicitly refuse. The trusted UID/root can mutate outside this API; this is not sealed authentication.

Exclusive lock creation elects the sole initializer internally. Contenders never adopt lock-only or partial initialization. Lock inode is never deleted or replaced. Files and directories are synced before publication; both incomplete and generations are synced after cross-directory rename; selector replacement is followed by root sync. Durability uncertainty returns ErrRecoveryRequired. Idempotent selection reconfirms both publication parents and root durability, including after an uncertain prior call. Recover verifies and preserves evidence; incomplete or ambiguous remnants refuse and require an external decision. No cleanup, GC or fallback is provided.

Full destination writer fencing, historical writer inventory, plugin preservation, restricted authority, active catalog qualification, actual distro and no-SSH capability tests remain open. Source publication requires a separate exact candidate/mixed-version review and exact source CI; local gates are not that approval.
