# Policy-backed authored instructions

When the reviewed release contains a fleet `route_policy`, `upkeeper author`
passes the fleet document's canonical rendering to the generator from the exact
pinned omarchy-setup commit. This is the same JSON-as-YAML byte sequence fleet
convergence installs. Its SHA256, rather than the original YAML fixture's digest,
is the provenance embedded in generated instructions and native role files.

The generator runs with an empty private HOME and TMPDIR. The explicit policy
is a separate mode 0400 file outside the extracted source and output trees:

```
config/bin/agents-instructions-gen --root EXACT_SCRATCH_CHECKOUT --policy EXPLICIT_FILE
config/bin/agents-instructions-gen --root EXACT_SCRATCH_CHECKOUT --policy EXPLICIT_FILE --check
```

Both calls must succeed. Author requires all eight legacy instruction outputs
and all five Claude agents and five Codex profiles declared by the generator
interface. The Claude imported instructions come from generated scratch output.
Missing, linked, nonregular, empty, invalid text or unsupported-mode output
refuses before manifest replacement. Author preserves generated bytes and modes,
checks that policy and pinned source remain unchanged, and refuses output
mutation during the generator's check.

Native ownership is limited to the exact files
`.claude/agents/{reader,executor,reviewer,critical-reviewer,planner}.md` and
`.codex/{reader,executor,reviewer,critical-reviewer,planner}.config.toml`.
The existing `DerivedSources.Instructions` map carries them. No native directory
is claimed or cleaned; unrelated released native files survive unchanged.
The existing legacy `.config/agents` directory retirement behavior is retained.
An empty scratch HOME has no OpenCode configuration, and generation must not
create or capture one. Existing unrelated manifest files remain carried.

Steward remains the sole route-policy schema authority. Existing release
validation separately checks configured catalog authorization. Generated
projection never establishes readiness, quota, credentials, tools, permissions
or deployment authority. Without `route_policy`, the legacy author API and
projection remain unchanged. Shared instruction ownership remains inert.

`TestAuthorPinnedPolicyGenerator` runs through actual author dispatch with the
real consumer on PATH and an isolated local clone of the published generator.
Offline repository CI may omit both opt-in variables. Supplying either requires
both `M14_GENERATOR_REPOSITORY` and `M14_GENERATOR_COMMIT`, with the exact published
commit `88d9b534a6648e2615037dc3a655e6a8d0e9bebc`, clean tracked source and tree
`db9750657bac6f3fbb2f0ded4a139c0f585333ec`; invalid inputs fail. The declared M14
verifier supplies both, so this integration must run without skipping.
